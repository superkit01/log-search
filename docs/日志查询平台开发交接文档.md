# 日志查询平台开发交接文档

版本：2026-10-28。应用名、包名与模板名已替换为通用示例，实际值请以部署配置为准。目标 Elasticsearch：7.17.29。本文描述现有日志的索引、数据结构和查询契约，供查询平台前后端开发使用；不要求部署链路追踪后端。

依据：业务方提供的真实 ES 文档、当前 Logback JSON 配置、Logstash pipeline 与索引模板。尚未直接访问线上 ES，字段的最终类型应以线上 mapping / field_caps 为准。

## 1. 数据流与归属

```text
业务服务 / Gateway
  → Logback TCP Appender：单行 JSON
  → Logstash：规范化 namespace、env，计算每日索引
  → Elasticsearch 7.17.29
  → 查询平台后端访问 ES，前端展示结果
```

- `namespace`：平台 / 业务空间，例如 ems；同一个平台的多个应用使用相同 namespace。不是应用名，也不强制等于 Kubernetes namespace。
- `env`：部署环境，例如 dev、test、prod。
- `app`：服务 / 应用名，例如 gateway、api-server。
- Logback 将 namespace、env、app 作为固定 JSON 字段发送，不要求业务逐条写 MDC。
- 一条 ES 文档对应一次日志事件；一条异常日志可以在 stack_trace 字符串内包含多行堆栈。

## 2. 索引命名与时间

```text
app-log-{namespace}-{env}-{yyyyMMdd}
```

示例：

```text
app-log-default-dev-20261028
app-log-ems-dev-20261028
app-log-ems-prod-20261028
```

同平台、同环境、同一天的多个应用写入同一个索引，按 app 区分。

| 规则 | 约定 |
| --- | --- |
| 日期来源 | 日志事件的 @timestamp，非查询时间或 Logstash 收到时间 |
| 索引日期时区 | 当前默认 Asia/Shanghai，可由部署配置 INDEX_TIMEZONE 调整 |
| 日期格式 | yyyyMMdd；MM 为月份，不能用表示分钟的 mm |
| namespace、env | 转小写；非 a-z / 0-9 / 下划线 / 短横线的字符替换为短横线，连续短横线合并，去除首尾短横线及下划线，最多 64 字符 |
| 缺失或空值 | Logstash 规范化为 unknown；当前实际 namespace=default 是应用配置值，不代表 unknown |
| 生命周期 | 普通每日索引；当前配置没有自动删除保留策略 |

真实样例的 @timestamp 为 `2026-10-28T06:46:56.518Z`，对应北京时间 `2026-10-28 14:46:56.518`，应写入 `app-log-default-dev-20261028`。这里的索引名称按配置推导，实际 _index 请从 ES 查询结果核对。

查询范围采用左闭右开 `[startTime, endTime)`。后端按索引分日时区枚举涉及的日期，查询这些索引，再用 @timestamp range 精确过滤。跨日必须同时覆盖相关日期；不要根据索引名拆分来反推 namespace / env，因为二者可包含短横线。索引时区若变更，历史查询需同时兼容旧分日边界。

## 3. 真实 ES 数据样例

```json
{
  "level": "INFO",
  "env": "dev",
  "@timestamp": "2026-10-28T06:46:56.518Z",
  "namespace": "default",
  "host": "10.197.180.30",
  "message": "请求Url:/api/smartEsm/inspectionCycle/page,TraceID:",
  "thread_name": "reactor-http-epoll-16",
  "logger_name": "com.example.gateway.filter.AuthFilter",
  "level_value": 20000,
  "@version": "1",
  "app": "gateway",
  "port": 38528,
  "traceId": "d6bcc448340eed4a49fc01ddf2bed4d6",
  "spanId": "170f942bf25dff7d"
}
```

这是文档的 _source。实际搜索结果外层另含 `_index`、`_id`、`sort` 等 ES 元数据；查询平台需要保留 _index + _id，用于唯一定位日志。日志行唯一标识不能使用 traceId 或 spanId，同一个 Span 可以输出多条日志。

## 4. 字段字典

| 字段 | JSON 类型 | 含义 / 来源 | 查询与展示 |
| --- | --- | --- | --- |
| @timestamp | string，ISO 8601 | 日志事件发生时间；样例 Z 表示 UTC | ES date；范围过滤、排序，页面默认转北京时间 |
| namespace | string | 平台 / 业务空间 | 精确过滤、平台选择器 |
| env | string | 环境 | 精确过滤、环境选择器 |
| app | string | 应用名，当前真实日志使用此字段 | 精确过滤、应用选择器；不是 serviceName |
| level | string | TRACE / DEBUG / INFO / WARN / ERROR 等 | 精确过滤，多选用 terms |
| level_value | number | Logback 数值级别，例如 INFO=20000 | 可展示或排序；不要当作 HTTP 状态码 |
| message | string | 日志正文 | 全文搜索、详情展示 |
| logger_name | string | Logger 名称，通常为类全限定名 | 精确过滤、展示；不等于一定有方法名或行号 |
| thread_name | string | 产生日志的线程名 | 精确过滤、展示 |
| traceId | string，可缺失 | 32 位十六进制 Trace ID | 精确关联跨服务日志 |
| spanId | string，可缺失 | 16 位十六进制当前 Span ID | 当前操作内的日志过滤 |
| parentSpanId | string，可缺失 | 线程池 wrapper 记录的父 Span ID | 只在相应任务作用域可用；不是所有 HTTP / MQ Span 都输出 |
| taskId | string，可缺失 | 线程池 wrapper 的任务关联 ID | 关联任务提交与执行日志；同一任务可有多条日志 |
| stack_trace | string，可缺失 | 有 Throwable 时编码的异常堆栈 | 详情折叠展示、可选全文搜索；不保证 ERROR 日志都有堆栈 |
| host | string，当前样例 | TCP 接收端记录的对端地址等连接信息 | 传输链路线索；经过代理 / NAT 时不等于真实实例 IP |
| port | number，当前样例 | TCP 连接对端端口；样例为 38528 | 仅作辅助信息；不是应用 HTTP 端口或 Logstash 监听端口 |
| @version | string | 当前为 "1" 的事件版本字段 | 保留即可，不用于业务筛选 |

host / port 受 TCP 插件和 ECS 配置影响，后续可能变成嵌套元数据或不再出现，页面必须允许缺失。需要稳定的实例身份时应另行约定 instanceId / podName，目前没有这类字段。

当前没有约定 namespace 之外的租户标识，也没有自动输出 event、messageId、deliveryAttempt、HTTP 状态码、耗时等结构化字段。不要从不存在的字段构建强制筛选器。

样例正文的 `TraceID:` 虽然为空，顶层 `traceId` 仍然有效。查询和关联必须使用顶层 traceId，不能依赖正文中的 TraceID、SkyWalking tid 等字符串。

## 5. Mapping 与兼容处理（开发前必须核对）

当前模板 `app-log-template` 适用 app-log-*，显式定义：

- date：@timestamp。
- keyword：namespace、env、serviceName、traceId、spanId、parentSpanId、taskId、level、thread_name、logger_name。
- text：message、stack_trace。

**模板目前没有显式定义 app，而真实日志使用 app。** 默认动态映射下它通常为 text + app.keyword，但线上其他模板可能改变该行为，因此不能未经核对就写死。

```text
GET /app-log-default-dev-20261028/_mapping
GET /app-log-*/_field_caps?fields=app,app.keyword,serviceName,namespace,env,traceId,spanId,parentSpanId,taskId,level,thread_name,logger_name,host,port,@timestamp
GET /_template/app-log-template
```

字段适配建议：

| 场景 | 做法 |
| --- | --- |
| app 为 keyword | term / terms / 聚合使用 app |
| app 为 text，且 app.keyword 存在 | 精确过滤及聚合使用 app.keyword；返回仍读取 _source.app |
| 老索引只有 serviceName | 按索引的字段能力适配，界面可回退显示 serviceName；不要把当前主字段换成 serviceName |
| 同名字段跨索引类型冲突 | 缩小到兼容索引范围，或分组查询后统一响应，不能假定一个 DSL 通吃 |
| 老索引缺少某字段 | 允许缺失；缺失不等于空字符串，不应导致整页失败 |

建议后续把 app 显式映射为 keyword，作为统一的新索引规范；这属于待确认改进，不是现有线上类型的承诺。修改模板不会改变已经创建的索引类型，历史数据需按实际映射兼容。

## 6. 查询功能与 DSL

最小功能：平台、环境、应用、时间范围、级别、正文关键词、traceId、spanId、taskId、logger；结果列表、异常详情、同 Trace 日志跳转。

精确字段用 filter 中的 term / terms；正文用 match 或 match_phrase。message 为默认 text，未配置中文分词插件，不应承诺高级中文语义检索。不要默认使用前导通配符实现任意子串匹配。

下面例子假设已确认 app.keyword 可用，其余精确字段为 keyword。

### 6.1 条件查询

```text
POST /app-log-default-dev-20261028/_search?ignore_unavailable=true&allow_no_indices=true
```

```json
{
  "size": 100,
  "timeout": "5s",
  "track_total_hits": 10000,
  "_source": ["@timestamp", "namespace", "env", "app", "serviceName", "level", "message", "thread_name", "logger_name", "traceId", "spanId", "parentSpanId", "taskId", "host", "port"],
  "query": {
    "bool": {
      "filter": [
        {"term": {"namespace": "default"}},
        {"term": {"env": "dev"}},
        {"term": {"app.keyword": "gateway"}},
        {"terms": {"level": ["INFO", "WARN", "ERROR"]}},
        {"range": {"@timestamp": {"gte": "2026-10-28T14:00:00+08:00", "lt": "2026-10-28T15:00:00+08:00"}}}
      ],
      "must": [{"match_phrase": {"message": "inspectionCycle"}}]
    }
  },
  "sort": [{"@timestamp": "desc"}]
}
```

没有关键词条件时删除 must；没有应用限制时删除 app 条件。range 应始终保留。列表不默认返回 stack_trace，点击详情时按 _index + _id 获取完整文档，避免大量长堆栈拖慢列表。

### 6.2 查看同一 Trace 的跨应用日志

```text
POST /app-log-default-dev-20261028/_search
```

```json
{
  "size": 200,
  "query": {
    "bool": {
      "filter": [
        {"term": {"namespace": "default"}},
        {"term": {"env": "dev"}},
        {"term": {"traceId": "d6bcc448340eed4a49fc01ddf2bed4d6"}},
        {"range": {"@timestamp": {"gte": "2026-10-28T00:00:00+08:00", "lt": "2026-10-29T00:00:00+08:00"}}}
      ]
    }
  },
  "sort": [{"@timestamp": "asc"}]
}
```

Trace 跳转要去掉原先单个 app / level / message 等限制，保留授权范围、namespace、env 与明确的时间范围；否则会漏掉其他服务或级别的关联日志。跨日扩大索引范围。匹配超过 size 时继续分页，不能把前 200 条当成完整链路。

一个 Trace 可以含多个任务、HTTP、MQ 操作；日志关联不等于完整调用树。现有数据没有完整的每个 Span 的 parentSpanId、起止时间和 duration，平台一期可展示时间线及显式线程父子关系，不能据此构造可靠的完整调用拓扑。跨机器时钟偏差也可能影响时间顺序。

### 6.3 应用与级别统计

在平台、环境、时间范围过滤后做聚合，避免跨全量索引扫描。应用聚合字段按 mapping 选择 app 或 app.keyword。terms 聚合按 size 返回有限个桶；应用规模超过上限时要提供补充检索或 composite 分页，不能认为下拉列表一定完整。

```json
{
  "size": 0,
  "query": {"bool": {"filter": [
    {"term": {"namespace": "default"}},
    {"term": {"env": "dev"}},
    {"range": {"@timestamp": {"gte": "2026-10-28T00:00:00+08:00", "lt": "2026-10-29T00:00:00+08:00"}}}
  ]}},
  "aggs": {
    "apps": {"terms": {"field": "app.keyword", "size": 100}},
    "levels": {"terms": {"field": "level", "size": 10}}
  }
}
```

## 7. 分页与查询平台接口建议

默认每页 100，最大 500；默认最近 15 分钟，最大时间范围由平台配置。ES 默认 from + size 深分页受 10000 条窗口限制；连续翻页采用 PIT + search_after，不建议扩大 result window 来实现任意深页码。

```text
POST /app-log-default-dev-20261028/_pit?keep_alive=1m
```

用返回的 id 查询，路径不再带索引名：

```text
POST /_search
```

```json
{
  "size": 100,
  "pit": {"id": "替换为PIT_ID", "keep_alive": "1m"},
  "track_total_hits": 10000,
  "query": {"bool": {"filter": [
    {"term": {"namespace": "default"}},
    {"term": {"env": "dev"}},
    {"range": {"@timestamp": {"gte": "2026-10-28T00:00:00+08:00", "lt": "2026-10-29T00:00:00+08:00"}}}
  ]}},
  "sort": [{"@timestamp": "desc"}, {"_shard_doc": "desc"}]
}
```

下一页保持查询和排序不变，将上一页最后一条 hit.sort 数组原样放入 search_after，使用最新响应的 pit_id。不要自己转换排序值或用 _id 代替 _shard_doc。PIT 内相同时间的日志由 _shard_doc 稳定区分，不代表真实因果先后。

翻页期间 PIT 是快照，不包含新到日志；用户刷新时重新建立 PIT。关闭页面或新查询时释放 PIT；过期后提示刷新，不能把旧 search_after 搬到新 PIT 中继续。无匹配日期索引时后端应返回空列表，不把无索引异常直接暴露给用户。

```text
DELETE /_pit
```

```json
{"id": "替换为PIT_ID"}
```

建议平台自行封装接口（下列是建议契约，不是现有接口）：

| 接口 | 输入 / 行为 |
| --- | --- |
| POST /api/logs/search | namespace、env、apps、levels、startTime、endTime、keyword、traceId、spanId、taskId、loggerName、pageSize、cursor |
| GET /api/logs/detail | index、id；返回完整 _source，后端校验索引所属范围 |
| POST /api/logs/facets | namespace、env、时间范围；返回应用与级别等可用选项 |

search 返回 items、nextCursor、total.value、total.relation、tookMs、timedOut、partial。items 至少包含 index、id 与上述列表字段。relation=gte 表示下界（如 10000+），不能显示为精确总量；ES timed_out 或 _shards.failed 非零时标记结果不完整，不显示为确定的“无日志”。cursor 由后端封装 PIT ID、排序值及查询标识，改动筛选条件必须开始新查询。

后端统一管理 ES 地址、认证与 namespace / env 可见范围，不让浏览器直连 ES。输入 index、namespace、env 由后端按允许值校验；普通用户不能传任意通配符扩大索引范围。HTTP / TCP 的 ES 连接配置由部署人员提供，不在业务前端配置中暴露。

## 8. 验收用例与待提供信息

| 场景 | 期望 |
| --- | --- |
| 同平台不同 app | 同索引可查，按 app 可精确过滤 |
| 不同 namespace / env | 索引与筛选隔离，界面展示正确平台 / 环境 |
| 样例 Trace | 查询顶层 traceId 能找到真实样例，正文 TraceID 为空不影响 |
| 启动日志无 traceId | 列表正常展示，关联跳转不可用 |
| 线程池日志 | 可按 taskId 查看提交、执行，并显示存在的 parentSpanId |
| 毫秒时间相同、超过一页 | PIT + search_after 翻页不重不漏 |
| UTC 16:00 跨北京时间午夜 | 索引日期切换正确，时间范围没有漏查 |
| 有异常 / 无异常 | stack_trace 可折叠，缺失不报错 |
| 老索引 app 类型不同 | 适配 mapping 或明确提示类型冲突 |
| 空索引 / 超时 / 分片失败 | 区分无结果、超时和部分结果 |

开发联调前由部署方补充：ES 地址与认证方式、实际 _index、mapping / field_caps 结果、可见 namespace / env 列表、索引保留天数、允许查询范围和分页上限。日志并非即时可见，ES refresh 与传输缓冲可能造成短暂延迟。
