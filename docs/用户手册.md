# 日志查询（Log Search）使用手册

日志查询平台，集中查询各业务系统的日志，支持按环境、应用、级别、时间、关键词、链路 ID 等多维度筛选与展示，并提供级别分布图表、日志折叠、链路下钻、查询分享等便捷能力。

> 目前仅支持测试环境(10.197.190.30)

## 访问地址

```
http://10.197.220.100:18080
```

---

## 查询条件

| 条件 | 说明 |
|------|------|
| **级别** | `DEBUG / INFO / WARN / ERROR`，可多选；|
| **方向** | `倒序`（默认，新→旧）/ `正序`（旧→新） |
| **环境** | 单选，目前仅查询测试环境的日志 |
| **应用** | 下拉单选，`不限` 表示全部应用 |
| **时间** | 起止时间，**必填**；快捷按钮 `1h` `3h` `今天` |
| **链路 ID** | TraceId，精确匹配 |
| **消息 ID** | MessageId，精确匹配；用于查询同一条 MQ 消息的发布、消费及相关业务日志，可随分享链接传递 |
| **关键词** | 匹配日志正文，支持 `&&`(且) 和 `\|\|`(或)|

## 查询结果

- **图表**: 按分钟桶堆叠的级别柱状图，一眼看错误集中在哪个时间点。
- **日志行**: 左侧东八区时间戳（日期 + `时:分:秒.毫秒`），中间是标签 + 正文。
- **标签点击复制**: 点 `app`、`level` 等标签直接复制值到剪贴板（按位置自动上色，不同部署的标签 key 都有颜色）。
- **超长日志折叠**: 单条超过 10 行自动折叠，点 `展开 >>` 看全文。
- **继续加载**: 滚到底部自动加载下一页（游标分页），顶部显示「已加载 N 行」。
- **同毫秒顺序**: ES 按时间和 `sequence` 同向排序，序号仅表示同一进程本次运行内的日志事件顺序；跨服务、实例或重启后的序号不能用于推断业务因果关系。旧日志没有序号仍可查询。
- **ES 分页快照**: 一次查询使用固定快照，继续加载不会跳过同毫秒日志。每次翻页续期 2 分钟；停留超过 2 分钟后若提示快照失效，重新点击查询即可。查询后新增的日志需要重新查询才能看到。
- **链路追踪**: 
    日志里带 `tid` 标签的行，**点击 `tid` 标签**会在新窗口打开该链路的完整日志：
    - 自动以当前时间为中心、**前后各 15 分钟**
    - 清空应用/级别/关键词，只按 TraceId 过滤
- **分享查询**：右上角分享按钮，把当前全部查询条件编码进 URL 复制，粘给同事打开就是同样的查询（含时间范围）。

## 其他

- **主题**：右上角切换深色/浅色，记忆在浏览器。
- **记忆偏好**：环境、级别、方向会记在浏览器时间范围每次默认「今天 00:00–23:59」。

## sequence 部署配置

1. 业务服务合并 [Logback 配置](logback-spring-sequence.xml) 中的 `sequenceNumberGenerator` 和 Encoder 内的 `SequenceJsonProvider`，然后重启业务服务。保留自己的应用名、环境及原有 Appender 配置。序号直接由 Encoder 写入数字字段，不需要 MDC 白名单。
2. 替换服务器 `logstash/templates/app-log-template.json`，将 `sequence` 映射为 `long`，重启 Logstash 加载新模板。Logstash pipeline 不需要变更。
3. 模板只影响新建索引；对正在写入的现有索引补充映射，例如在 ES Dev Tools 执行：

   ```http
   PUT /app-log-*/_mapping
   {
     "properties": {
       "sequence": { "type": "long" }
     }
   }
   ```

   若现有 `sequence` 已是其他类型，需使用新索引或迁移，不能原地更改字段类型。旧日志不会自动补出序号。
4. 重新构建部署 log-search。ES 分页要求支持 PIT 的版本（当前部署的 7.17 支持）；旧的时间戳游标和 Loki 查询继续兼容。
