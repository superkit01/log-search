# 日志查询平台开发交接文档

本文约定查询平台读取的存储字段。应用日志采集、传输和写入存储由接入方负责，项目不再维护 Logback XML 配置。

## 1. 输入日志结构

以业务方提供的 `LogstashEncoder` 为输入约定：

- `customFields` 输出顶层 `app`、`env`、`namespace`，分别来自应用名、环境和平台配置。
- MDC 白名单包含 `traceId`、`spanId`、`parentSpanId`、`taskId`、`messageId`。应用需要在产生日志的上下文中设置实际值；白名单本身不会生成 ID，未设置时字段可以缺失。
- `SequenceJsonProvider` 对应 `sequence`。需要采集端实际提供有效的事件序号，不能仅凭 provider 声明保证已有有效序号。
- `includeContext=false` 不把 LoggerContext 属性整体写入日志；查询所需固定字段仍须通过上述明确字段提供。
- 存储中的字段使用下表名称和大小写，不将这些字段包在 `mdc`、`context` 等对象内。采集端格式不同时，应在写入前转换成此结构。

```json
{
  "@timestamp": "2026-11-04T18:00:00.123+08:00",
  "namespace": "pts",
  "env": "test",
  "app": "boeet-preventive",
  "level": "ERROR",
  "message": "MQ 消息处理失败",
  "sequence": 12345,
  "logger_name": "com.example.MessageConsumer",
  "thread_name": "consumer-1",
  "traceId": "trace-123",
  "spanId": "span-456",
  "parentSpanId": "span-123",
  "taskId": "task-789",
  "messageId": "mq-123",
  "stack_trace": "java.lang.IllegalStateException: 示例异常\n\tat com.example.MessageConsumer.consume(MessageConsumer.java:42)"
}
```

## 2. 存储字段

| 字段 | JSON 类型 | 要求 / 来源 | 查询平台用途 |
|---|---|---|---|
| `@timestamp` | string | 必需；带时区的 ISO 8601 时间，支持毫秒及更高精度 | 时间范围过滤与排序；ES 时间无法解析的记录会被跳过 |
| `namespace` | string | 平台标识，来自 customFields；与 ui.namespaces 及索引中的平台值一致 | 平台选择、ES 索引解析和精确筛选 |
| `env` | string | 环境标识，来自 customFields；与平台下配置的环境值一致 | 环境筛选，例如 test、release、prod |
| `app` | string | 应用名，来自 customFields；与 ui.apps 配置值一致 | 应用筛选及标签展示 |
| `level` | string | 日志级别，例如 DEBUG、INFO、WARN、ERROR | 级别筛选；返回时规范化为小写 |
| `message` | string | 日志正文 | 关键词检索和正文展示 |
| `sequence` | integer，可选 | 日志事件序号；ES 使用 long，不使用浮点数存储 | ES 同时间戳排序；展示时保留整数精度；旧日志缺失时兼容 |
| `traceId` | string，可选 | MDC 链路 ID | 链路筛选；ES 返回时同时生成兼容标签 tid |
| `spanId` | string，可选 | MDC 当前 Span ID | 当前操作日志筛选 |
| `parentSpanId` | string，可选 | MDC 父 Span ID | 父操作日志筛选 |
| `taskId` | string，可选 | MDC 线程任务 ID | 线程任务关联查询 |
| `messageId` | string，可选 | MDC MQ 消息 ID | MQ 消息关联查询 |
| `logger_name` | string，可选 | Logger 名称，通常为类全限定名 | 标签展示；当前没有独立 Logger 筛选条件 |
| `thread_name` | string，可选 | 产生日志的线程名 | 标签展示 |
| `stack_trace` | string，可选 | 异常堆栈，内部换行使用 JSON 转义 | ES 返回时追加到正文中展示；关键词检索目前只查询 message |
| `host` | string，可选 | 应用实例或采集端补充的主机信息 | 标签展示，具体含义由采集链路约定 |
| `level_value`、`@version`、`port` | number / string，可选 | 编码器或采集端附加字段 | 当前不作为筛选条件，也不在可见标签白名单中 |

关联 ID 按字符串精确匹配，不要求固定长度或十六进制格式。字段缺失表示没有提供相应上下文，不能自动推断为处理失败或没有调用关系。`sequence` 只用于同一进程本次运行内的事件顺序，不用跨实例序号判断因果；日志唯一定位使用 ES 的 `_index` 和 `_id`，不能使用 traceId 或 spanId 代替。

## 3. Elasticsearch 接入

推荐字段类型：`@timestamp` 为 date，`sequence` 为 long，正文与堆栈为 text，平台、环境、应用、级别、所有关联 ID、Logger 和线程名为 keyword。实际字段类型以目标索引 mapping 为准；模板变更不会自动修改旧索引。

查询字段映射按 `storage.elasticsearch.fields` 配置：

- `env`、`app`、`level`、`traceId` 通过相应配置项指定精确查询字段；纯 keyword 使用原字段，text 的 keyword 子字段使用 `.keyword` 路径。
- `namespace`、`spanId`、`parentSpanId` 使用同名字段精确查询，接入时应映射为 keyword。
- `taskId`、`messageId` 同时兼容原字段与 `.keyword` 子字段。
- ES 旧日志中的 `serviceName` 可作为 app 展示的兼容回退，不代替接入时明确提供 app。

示例索引模式为 `app-log-{namespace}-{env}-{yyyyMMdd}`，在配置的 index_timezone 中解析日期，跨日期查询展开涉及的索引。namespace、env 和实际索引值须保持一致，查询平台不负责修正写入端字段或创建索引模板。分页使用 PIT + search_after，排序字段为 `@timestamp`、`sequence`、`_shard_doc`；目标 ES 需支持 PIT。

## 4. Loki 接入

上述 JSON 是业务日志的字段约定，不能直接视为 Loki Push API 请求体。采集端需把日志时间、正文、标签和 structured metadata 转换为 Loki 所需结构。

当前 Loki 实现使用 env、app、level 作为 stream labels；链路 ID 通过 structured metadata 的 `tid` 查询，接入方需将 traceId 转为 tid；spanId、parentSpanId、taskId、messageId 同样通过 pipeline filter 查询对应 metadata。仅将 ID 放进未解析的 JSON 正文无法满足这些结构化查询。

当前 Loki 查询没有按 namespace 构造选择器，不能依靠页面的平台选项实现 Loki 的平台隔离；如需多平台隔离，接入前应明确独立租户或存储端隔离方案。

## 5. 查询接口与开发入口

HTTP 与 MCP 共用 `internal/query`，存储实现位于 `internal/storage/elasticsearch` 和 `internal/storage/loki`。请求时间为 Unix 秒；limit 支持 1–1000，未传时使用 default_limit。返回 total 仅为本页数量，不是全量命中数。

详见[查询接口](../api/查询接口.md)、[MCP 接入](../integrations/MCP接入.md)及[用户手册](../guides/用户手册.md)。
